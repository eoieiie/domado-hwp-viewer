# 도마도 HWP 뷰어

한컴오피스 없이 `.hwp` / `.hwpx` 문서를 읽는 macOS 앱.

맥에는 한글 문서를 볼 무료 수단이 사실상 없다. 한컴오피스는 유료 구독이고,
온라인 변환 사이트는 학교 서류를 남의 서버에 올려야 한다.

- **의존성 0** — 표준 라이브러리와 시스템 프레임워크만 사용
- **1.1MB** — Electron 계열이면 수십 MB
- 파일이 밖으로 나가지 않음 (네트워크 통신 없음)

## 기능

- 드래그 앤 드롭 / `⌘O` / Finder "다음으로 열기"
- **표를 실제 격자로 복원** — 행·열 주소와 병합(span)까지
- 문서 내 검색 (일치 항목 하이라이트)
- **텍스트 바꾸기** — 서식·표·이미지를 건드리지 않고 본문만 치환, 새 파일로 저장
- **압축 풀기·만들기** — 한글 파일명이 깨지지 않는다 (아래 참고)
- 이미지 추출·내보내기 (썸네일 미리보기)
- `.txt` 저장 (`⌘S`), 전체 복사 (`⌘⇧C`)
- 확장자가 틀려도 컨테이너 시그니처로 판별

## 빌드

```bash
swift build -c release --product HwpViewer
```

CLI만 필요하면:

```bash
swift run hwpcli 문서.hwp                    # 본문 출력
swift run hwpcli 문서.hwp -t                 # 표 구조로 출력
swift run hwpcli 문서.hwp -g                 # 이미지 목록·추출
swift run hwpcli 문서.hwp -r                 # 문단 구조 점검 (아래 참고)
swift run hwpcli 문서.hwp -e "옛말=>새말"     # 치환 → 문서_수정.hwp
```

## 포맷 메모

### .hwp — 3겹 구조

```
OLE Compound File (CFBF)
└─ BodyText/Section0
   └─ raw DEFLATE
      └─ 레코드 스트림: [32비트 헤더][페이로드]
         헤더 = tag(10) | level(10) | size(12)
         size == 0xFFF 이면 다음 4바이트가 실제 크기
```

본문은 `tag == 67`(PARA_TEXT), UTF-16LE.
제어문자 중 `1~8, 11~23`은 **16바이트(8 units)** 를 차지한다. 2바이트로 세면
이후 모든 글자가 밀린다.

레벨은 컨테이너마다 2씩 증가한다 — 본문 문단 1, 표 셀 3, 중첩 표 5.

### .hwpx — zip + XML

`Contents/section0.xml` 안에서 `<hp:p>`가 문단, `<hp:t>`가 텍스트 런,
`<hp:tbl>`이 표. 훨씬 단순하다.

## 압축 — 한글 이름이 깨지는 두 방향

**윈도우 → 맥.** 알집과 탐색기는 파일명을 CP949로 쓰고 "UTF-8이다"라고 알리는 비트를
켜지 않는다. macOS는 비트가 없으면 CP437로 읽어서 `과제제출_황병주.hwp`가
`????????_??????.hwp`가 된다.

**맥 → 윈도우.** 이쪽이 덜 알려져 있다. macOS는 파일명을 자모가 분리된 형태로 들고
있어서, 맥 기본 압축은 그걸 그대로 넣고 UTF-8 표시도 안 한다. 자모 분리된
`보고서 최종본.hwp`을 넣고 비교하면:

| | UTF-8 플래그 | 이름 | |
|---|---|---|---|
| macOS 기본 압축 (`ditto`) | **X** | 47바이트 | **자음·모음 분리된 채로** |
| 도마도 | O | 30바이트 | 합쳐서 |

두 가지가 동시에 틀린다. 그리고 **만든 맥에서는 멀쩡해 보여서 알 방법이 없다.**

푸는 쪽은 `FileManager`가 아니라 POSIX로 쓴다. `URL`과 `FileManager`는 경로를
`fileSystemRepresentation`으로 통과시키면서 분해하기 때문에, 이름을 복구해놓고도
디스크에는 다시 분리된 채로 적힌다.

압축 항목 이름은 만든 사람이 정한 문자열이다. `../../../.ssh/authorized_keys`도 적법하다.
`..`는 해석하지 않고 거부한다.

## 텍스트 바꾸기 — 안 깨지게 만드는 법

`.hwp`를 고치다 실패하면 **경고 없이 열리지 않는 파일**이 남는다. 그래서 이 기능은
"무엇을 하느냐"보다 **"무엇을 거부하느냐"** 로 설계했다.

### 1. 컨테이너를 다시 만들지 않는다

FAT·DIFAT·디렉터리·미니스트림을 재구성하면 어느 하나만 틀려도 문서가 깨진다.
그래서 아무것도 재구성하지 않는다. **본문 섹터에 덮어쓰고, 기록된 길이만 고치고,
나머지 바이트는 원본 그대로 복사한다.** 자리가 모자라면 파일 끝에 섹터를 붙이되,
할당표가 이미 "빈 자리"로 표시한 번호만 쓴다. 그것도 안 되면 **거부한다.**

파일 중간의 빈 섹터는 재사용하지 않는다 — 이 리더가 모르는 무언가가 참조하고
있을 수 있고, 끝에 붙이는 건 무엇과도 충돌하지 않는다.

### 2. 필드 오프셋을 추측이 아니라 검증으로 쓴다

`PARA_HEADER`의 글자 수·서식 수·줄 정보 수 오프셋은 공개 스펙이 아니라 실제
문서를 읽어 알아낸 것이다. `-r`이 그 추측을 매번 재검증한다 — 머리 레코드가
신고한 개수를 뒤따르는 레코드에서 다시 세어 대조한다.

```
$ hwpcli 문서.hwp -r
✓ 모든 문단에서 머리 레코드와 본문·서식·줄 정보의 개수가 일치합니다.
```

편집 직전에도 같은 검사를 하고, 하나라도 어긋나면 그 문서는 건드리지 않는다.

이 검사가 실제로 버그를 잡았다. **문단의 레코드는 머리와 같은 레벨이 아니라 한
단계 아래에 있다**(lv0 헤더 → lv1 본문). 같은 레벨로 묶었더니 모든 문단이 "본문
0자"로 나왔고, 그대로 갔으면 모든 글자 위치를 엉뚱한 레코드에 썼을 것이다.

### 3. 애매하면 건너뛴다

- 제어문자(표·그림 앵커)를 가로지르는 일치 → 자를 수 없으니 **건너뛰고 보고**
- 바꿀 글자 **중간에서 서식이 바뀌면** → 새 서식이 무엇이어야 할지 알 수 없으니 건너뜀
- 원본 경로로 저장하려 하면 → 거부

### 4. 만든 파일을 다시 읽어 확인한 뒤에야 넘긴다

- 다시 파싱되는가
- 모든 문단이 의도한 텍스트와 **정확히** 일치하는가
- 본문 외 모든 스트림(DocInfo·BinData·PrvImage·Scripts…)이 **바이트 단위로 동일**한가

하나라도 실패하면 저장하지 않는다.

### 안 되는 것

- **`.hwpx` 수정** — 미지원(읽기는 됨). zip 쓰기가 필요하다
- **미니스트림(4KB 미만) 수정** — 거부한다. 실제 문서의 Section0은 항상 이보다 크다
- **`PrvText` 갱신 안 됨** — Finder 미리보기가 잠시 옛 텍스트를 보여준다.
  한글에서 저장하면 다시 만들어진다

## 검증

스펙 문서 없이 만든 파서라 **독립 구현 2개를 교차 검증**했다.
Python 참조 구현과 Swift 구현의 출력을 diff로 비교 — 120문단 완전 일치.

편집 결과는 **`olefile`(별도 CFBF 구현)** 로 다시 확인했다. 우리 리더가 우리
라이터를 확인하면 순환 논증이라서다. 실제 문서 5개에서:

| 확인 항목 | 결과 |
|---|---|
| 본문 외 스트림 (이미지 12개 포함) | 전부 바이트 동일 |
| 레코드 개수 | 3058 → 3058 (변화 없음) |
| 바뀐 레코드 | 의도한 문단의 헤더·본문·서식뿐 |
| 원본 파일 | 해시 동일 |

그리고 **한컴 한글에서 직접 열어 확인했다.** 구조가 맞다는 것과 한글이 받아들인다는
것은 다른 문제이고, 최종 판단은 한글만 내릴 수 있다. 위험 경로별로 4건:

| 경로 | 문서 | 결과 |
|---|---|---|
| 글자 늘림 → **섹터 신규 할당** | 신청서 172,544 → 173,056바이트 | 정상 |
| 글자 줄임 | 신청서 | 정상 |
| 큰 문서 + 그림 12장 | 사업계획서 4.2MB | 정상 |
| 문단 안에서 서식이 여러 번 바뀜 | 평가 가이드 | 정상 |

### 표 복원

`CTRL_HEADER`의 컨트롤 ID가 `tbl `이면 표가 열린다. 그보다 깊은 레코드가 표의
내용이고, `LIST_HEADER` 하나가 셀 하나다. 셀 주소는 페이로드 오프셋 8부터:

| 오프셋 | 필드 |
|---|---|
| 8 | col |
| 10 | row |
| 12 | colSpan |
| 14 | rowSpan |

머리말·꼬리말·캡션도 `LIST_HEADER`를 갖기 때문에, **표 컨트롤 바로 아래 레벨**
(`controlLevel + 1`)인 것만 셀로 받아들여야 한다. 이걸 빼먹으면 머리말 리스트가
셀로 잡혀 열 개수가 5만 단위로 튄다.
